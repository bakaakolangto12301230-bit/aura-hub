# Aura Hub

Create a premium, modern, frontend-only **3-in-1 SaaS customer-facing web application** combining three connected experiences into one unified platform:

**Merchandise · Events · Auto**

The goal is to create a website/application that customers genuinely enjoy browsing and using—not an administrative dashboard.

This is **not an admin dashboard**.

Do NOT design the experience around tables, analytics, sidebars, data-heavy widgets, management panels, or traditional SaaS dashboard layouts.

The backend, database, administration, analytics, and business management systems will be handled separately.

Your responsibility is to create the **customer-facing frontend experience**.

The user should feel:

> “Everything I might need is already here.”

They should be able to naturally discover products, explore event services, and find automotive services without needing to understand that they are interacting with three different business systems.

---

# CORE DESIGN PHILOSOPHY

Build the experience around this design equation:

**Apple-inspired Liquid Glass**

+

**Micro-interactions**

+

**Progressive disclosure**

+

**Intuitive navigation**

+

**Modern spatial layouts**

+

**Immersive visual storytelling**

+

**Customer-first UX**

+

**Contextual interactions**

===========================

**A unique next-generation 3-in-1 SaaS experience**

Take inspiration from the principles behind Apple's latest Liquid Glass design language:

* Depth

* Translucency

* Fluidity

* Refraction-inspired layering

* Responsive surfaces

* Spatial relationships

* Elegant motion

* Context-aware controls

* Minimal visual noise

* Clear hierarchy

Do not copy Apple's branding, website, components, or exact layouts.

Create an original visual identity inspired by the same level of refinement.

---

# THE MOST IMPORTANT PRINCIPLE

**Do not expose the complexity of the platform to the customer.**

The customer does not need to think:

> “This is an e-commerce module.”

or:

> “This is an event management module.”

or:

> “This is an automotive management module.”

Instead, they should think:

> “I need something to buy.”

> “I need to organize an event.”

> “I want to take care of my car.”

And the platform naturally guides them to the appropriate experience.

The three business categories should feel like **three worlds inside one beautiful platform**.

---

# CUSTOMER EXPERIENCE

Design the overall journey like this:

**Discover → Explore → Choose → Interact → Buy / Book → Confirm**

Not:

**Login → Dashboard → Sidebar → Data → Management**

The customer should be able to browse without feeling like they are operating business software.

---

# GLOBAL NAVIGATION

Create a beautiful floating Liquid Glass navigation bar.

It should feel lightweight and spatial rather than like a traditional website navbar.

Include:

* Brand/logo

* Home

* Shop

* Events

* Auto

* Search

* Cart

* Account/profile

* Contextual CTA

Do not overcrowd the navigation.

Use a floating, rounded glass surface with:

* Translucency

* Fine borders

* Subtle reflections

* Soft depth

* Controlled blur

* Elegant shadows

Keep the navigation compact.

---

# MICRO-INTERACTION APPLICATION SELECTOR

Do not use a large permanent three-way toggle.

Do not waste valuable screen space displaying:

**Events | Merchandise | Auto**

Instead, introduce the three experiences naturally through the navigation.

For example:

**Explore ▾**

or a compact contextual control containing the current destination.

When clicked, open a beautiful Liquid Glass drawer/popover containing:

### Shop

Browse merchandise, products, accessories, and collections.

### Events

Discover event services, packages, venues, and booking options.

### Auto

Explore car wash, detailing, packages, and appointments.

The interaction should feel like a small but delightful discovery moment.

Use:

* Spring animation

* Spatial expansion

* Glass layering

* Subtle icon movement

* Hover/touch response

* Active-state feedback

The drawer should appear connected to the navigation element rather than feeling like a generic dropdown.

# CONTEXTUAL NAVIGATION

Navigation should adapt to what the customer is doing.

For example:

When browsing Shop:

**Shop → Categories → Collections → Cart**

When browsing Events:

**Events → Occasions → Packages → Booking**

When browsing Auto:

**Auto → Services → Packages → Appointment**

Do not permanently display every possible navigation option.

Use **progressive disclosure**.

Show the customer what is relevant to the current context.

---

# SEARCH EXPERIENCE

Create a beautiful global search interaction.

Instead of immediately displaying a large search bar, use a compact search icon/button.

When activated:

* Expand smoothly

* Blur the surrounding interface

* Display recent searches

* Show suggested categories

* Display products/services/events

* Provide intelligent filtering

The search experience should feel like a focused interaction layer.

### Elevated Glass

### Immersive Glass

For:

* Important interactive moments

Do not blur everything.

* Large typography

# FRONTEND-ONLY REQUIREMENT

Build only the customer-facing frontend.

Use:

* React

* TypeScript

* Vite

* Tailwind CSS

* shadcn/ui

* Lucide React Icons

* Motion / Framer Motion

Use realistic mock data.

Use local frontend state for interactions.

Do NOT implement:

* Backend

* Database

* Authentication

* Payment processing

* API integrations

* Admin functionality

* Server-side functionality

Structure the components cleanly so backend functionality can be connected later.
